# TRIADA INVESTING Bot — Эталонная спецификация

## Структура файлов
```
main.py                  — точка входа, admin-команды (/start /status /test), Flask dashboard
config/config.py         — все настройки из .env / Environment Variables
modules/
  news_sources.py        — сбор из RSS (только финансовые ленты)
  ai_analyzer.py          — Groq JSON-анализ (llama-3.3-70b-versatile + fallback 8b)
  critic.py               — AI-критик рекомендаций через Google Gemini (другая модель)
  charting.py             — Finviz (основной) → yfinance+matplotlib (fallback) графики
  media.py                — статья → Wikimedia → Google CSE → Pexels/Pixabay → заглушка
  dedup.py                — антидубль (Upstash Redis / SQLite fallback), 2 уровня проверки
  formatter.py             — сборка HTML-постов, включая отображение мнения критика
  telegram_sender.py       — отправка в канал / админу
  pipeline.py               — связывает всё вместе + трек-рекорд рекомендаций
  scheduler.py              — APScheduler расписание всех задач
  storage.py                — SQLite (история, статистика, рекомендации)
.env.example
render.yaml                — конфиг деплоя на Render.com
SPEC.md                     — этот файл (эталон, сверяться перед правками)
```

## Типы публикаций
1. BREAKING — проверка каждые 2 минуты, 1 сообщение: [медиа + caption с blockquote expandable]
2. HOURLY — каждый час в :01, 2 сообщения: [фото + header], [blockquote с 3-4 новостями]
3. MORNING 08:00 МСК — 2 сообщения
4. EVENING 21:00 МСК — 2 сообщения
5. WEEKLY воскресенье 20:00 МСК — включает % точности рекомендаций за неделю
6. MONTHLY последний день месяца 21:30 МСК
7. Открытия бирж: Tokyo 03:00, London 11:00, New York 17:30 (без фото/AI)

## Медиа-логика
- Акция/индекс/крипта/нефть/золото/валюта с публичным тикером → график:
  Finviz (с браузерными заголовками запроса) → fallback yfinance+matplotlib
- Персона/компания без тикера/война/политика → фото:
  фото из RSS-статьи → Wikimedia (без ключа) → Google CSE → Pexels/Pixabay
  (опционально) → сгенерированная заглушка
- НЕ подставлять тикер по ассоциации для частных компаний (SpaceX ≠ TSLA)

## Антидубль (2 уровня)
1. По тексту заголовка — Jaccard similarity по словам
2. По теме+категории (subject_en) — ловит одно и то же событие с разных
   источников, даже если заголовки на разных языках/сильно переформулированы
- Хранилище: Upstash Redis (персистентно, приоритет) → SQLite fallback
  (сбрасывается при рестарте контейнера на бесплатном Render)

## AI-анализ
- Groq llama-3.3-70b-versatile (primary), llama-3.1-8b-instant (fallback)
- Обязательное поле `relevant` — жёсткий фильтр, явные негативные примеры
  (происшествия, соцдебаты без экономических решений, речи без конкретики)
- `subject_en` — англоязычное имя для точного поиска фото
- JSON-схема: relevant, post_type, category, subject, subject_en, title,
  summary, impact_level, impact_text, affected_assets, scenario,
  recommendation, recommendation_text, needs_chart, ticker

## AI-критик (Athena-подобная проверка рекомендаций)
- Вызывается ТОЛЬКО для BREAKING-постов с impact_level == "high"
  (бережём ограниченный бесплатный лимит Gemini — не на каждую новость)
- Модель — Google Gemini (gemini-2.5-flash), сознательно ДРУГАЯ, чем Apollo
  (Groq/Llama) — иначе критика слабая из-за самосогласия одной модели
- Если критик не согласен с рекомендацией — в посте показываются ОБА взгляда
  прозрачно (см. formatter.py:_rec), а не один самоуверенный вывод
- Если GEMINI_API_KEY не задан — бот работает без критика, публикует
  рекомендацию Apollo как есть (graceful degradation, не блокирует публикацию)

## Трек-рекорд рекомендаций
- При публикации BREAKING-поста с тикером и рекомендацией long/short (не
  neutral) — сохраняется цена актива на момент поста (storage.recommendations)
- Раз в час (scheduler: track_record) — сверяются рекомендации старше 24ч:
  long засчитывается верным при росте цены, short — при падении
- % точности за 7 дней — в /status и в еженедельном посте (WEEKLY)
- Neutral-рекомендации не отслеживаются (нет чёткого направления для проверки)

## Лидеры роста/падения MOEX
- Источник — MOEX ISS API (iss.moex.com), бесплатно, без ключа
- День — из текущего снимка доски TQBR (поле CHANGE)
- Неделя/месяц/год — текущий снимок + исторический снимок (с поиском
  ближайшего торгового дня назад, если попали на выходной/праздник)
- Строгое разделение по знаку: растущая бумага никогда не попадает в
  список падения, даже при малой выборке (см. modules/moex_leaders.py:
  _split_gainers_losers — это была реальная найденная и исправленная ошибка)
- Доставка: автопост раз в день в 19:00 МСК (после закрытия торгов) +
  команда /leaders по запросу в любой момент

## Что специально НЕ реализовано (осознанно)
- Twitter/X как источник — с 2026 года платный API без бесплатного тарифа,
  не добавлено, пока нет решения платить
